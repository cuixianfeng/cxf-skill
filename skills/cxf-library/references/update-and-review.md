# 更新、体检、验收和补洞小问题

## 1. 更新模式

**触发**：用户说「更新我的档案」「这条不对」「我换方向了」；崔先锋选题交回采纳或否掉的原因；补洞小问题有了回答。

**步骤**：

1. 读当前【我的档案】，找到版本行和「新信息记录」。
2. 把新信息和档案逐条比对，每条归一类：

| 类型 | 什么时候 |
|---|---|
| 新增 | 档案里没有的新事实、新故事、新观点 |
| 修改 | 跟旧内容冲突，或用户纠正 |
| 删除 | 用户说不对、不想要，或已经失效 |
| 不动 | 已经有了，或跟档案无关 |

3. 列改动清单给用户看，一次给完：

```text
这次准备改这些，你看看：
1. 新增｜第④节｜S04 关于第一次直播翻车……［事实］
2. 修改｜第②节｜方向1 从「职场新人避坑」改成「行政人的效率工具」｜原因：你说更想讲工具
3. 删除｜第⑦节｜P02｜原因：你说那条其实挺喜欢
回「全部确认」，或者告诉我哪条要改。
```

4. 用户确认后才写入：
   - 改动的节更新「更新：日期」；
   - 被删的条目留一行「已删除（日期，原因）」，编号不复用；
   - 在「新信息记录」末尾追加这次的改动；
   - 版本号+1，版本行写本次改了什么，如「v2｜2026-11-20｜本次：新增S04，调整方向1」。
5. 交出完整新版档案，提醒用户：存进 ima 后，把旧版本从同一个库里删掉或移到别的库，同一个库只留最新版，不然 AI 可能读到旧的。

**不要**：没确认就改；把后来的结论改进当初的记录里（当初的说法留着，在下面追加新说法和日期）；趁更新顺手改用户的原话。

## 2. 体检复核

**触发**：用户说「检查我的档案」，或档案里有节超过3个月没确认。

**检查这几项**：

1. 过期的节：「更新」日期超过3个月的，列出来。
2. 待确认清单：还有几条[待确认]、几条[推测]。
3. [推测]升级候选：已经有两次证据的[推测]，问用户能不能改成[事实]。
4. 方向的不成立条件：对照第⑦节的选题反馈，有没有方向已经触发了「不成立」。
5. 禁区和隐私：有没有 L0 信息混进来，有没有 L2 内容没标。

**体检结果的格式**：

```text
档案体检（v2，2026-11-20）
需要复核：第③节 4个月没确认；第⑥节 出镜方式可能变了
待确认：3条　推测：2条（O02 已有两次证据，可以转正）
方向提醒：方向2 连续3条选题被否，可能不成立
隐私：没发现问题
你想先复核哪条？
```

用户选了之后，一次复核一条：「这条还对吗？」答完走更新模式。

## 3. 验收

**触发**：刚写完档案，或用户说「验收」。

**做法**：只看档案，不看聊天记录，回答下面3–4个问题。每个答案注明依据编号。

1. 我的账号定位是什么？（陪聊档用户问成：我适合讲什么？）
2. 我最适合讲哪3个故事？
3. 我讲给谁听，他们卡在哪？
4. 照这份档案，给我出1条选题，并写依据。

**通过标准**：

- 每个答案都能指到档案里的编号或具体条目；
- 没有用到[推测]或[待确认]当事实；
- 用户看完说「对，像我」。

**没通过**：找出是哪一节空了或不准，当场补问一题，补完再答一次。用户说「先这样」就把缺口写进待确认清单。

崔先锋选题做验收时也用这套问题。崔先锋选题出的每条选题都要注明「依据：S03、O07」，拿不出依据的不出。

## 4. 和崔先锋选题的联动

**选题偏好**：崔先锋选题把采纳或否掉的原因交回来时，在第⑦节追加一句：

```text
P05｜2026-11-20｜否掉「三个AI表格神器」｜原因：「太像带货了，我不想推工具」［原话］
```

- 同一类选题连续被否3次，在第⑦节记一条偏好，标[推测]，放进待确认清单。
- 采纳且数据好的选题，在它引用的故事或观点后面加一句「已用于：选题名，日期」。

## 5. 补洞小问题

由崔先锋选题在推送选题时触发，本 Skill 只提供格式。每周最多2次，在档案「采访进度」里记本周次数。

**题目从哪来**（按顺序取）：

1. 待确认清单里的条目；
2. 档案里空着的节；
3. 最久没确认的节。

禁区里的话题不问。

**格式**（附在选题推送末尾，一题，一句话能答）：

```text
顺便问一句（补充你的档案用，可以不答）：
你上次说经常帮同事做排班表，最近一次是什么时候？
推荐答案：上周五，帮新来的同事排了下个月的班——是的话回「是」。
```

**回答之后**：回一句就记进「新信息记录」（类型写新增或修改，来源写「补洞小问题」），攒到用户下次说「更新档案」时一起整理进正文。用户没回或说「跳过」，不追问，跳过的话题记进禁区。
