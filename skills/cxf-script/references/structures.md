# 四类口播稿的结构

每类给出段落顺序、大约占比、每段要做的事和「必备料」。占比是参考，不硬套；段落之间要接得上，不写出小标题。

## 拆解复盘（约 2 分钟，450～550 字）

适合：「把某条视频 / 某个项目从头到尾拆一遍」「我是怎么做到的」。

| 段落 | 占比 | 要做的事 |
|---|---|---|
| 开头 | 约 12% | 晒真结果 + 留问题（怎么做到的）+ 说清今天拆几步 |
| 起因 | 约 13% | 当时看到了什么、手上有什么，大部分人会怎么做 |
| 第一步 | 约 20% | 他做的第一个不一样的决定：具体做了什么、为什么这么选 |
| 第二步 | 约 20% | 下一个关键动作：用了什么、怎么做、卡在哪、怎么解决 |
| 第三步（有才写） | 约 15% | 最后一个关键动作；没有就把前两步讲细 |
| 收住 | 约 12% | 回到结果，说出这件事背后一个能复用的判断 |
| 动作 | 约 8% | 观众今天就能照着做的一件事 |

必备料：
- 结果：数字或能证明的变化（播放、涨粉、客资、成交……）；
- 起因：从哪看到的、当时怎么想的；
- 每一步：具体做了什么、用了什么（工具、方法、素材），观众能看见的样子；
- 至少一个卡点或取舍：哪里难、放弃了什么；
- 能复用的那一条判断。

常见问题：每一步只说一句「我搭了个场景」「我挑了个开头」，不说怎么搭、怎么挑，观众听完学不到东西。

## 教程方法（约 2 分钟，450～600 字）

适合：「教你……」「几步做到……」「这个工具怎么用」。

| 段落 | 占比 | 要做的事 |
|---|---|---|
| 开头 | 约 12% | 点出观众的麻烦或想要的结果 + 他做到过的证明 + 今天给几步 |
| 为什么需要 | 约 10% | 不这么做会怎样（他自己踩过的坑最好） |
| 步骤 1～3 | 约 60% | 每步：做什么 → 具体怎么做 → 做到什么样算对；至少一步带例子 |
| 一个提醒 | 约 10% | 最容易做错的地方 |
| 动作 | 约 8% | 现在就去做第一步 |

必备料：每一步他自己做过的具体操作；至少一个真实用例或结果；一个他踩过的坑。

常见问题：步骤是正确的大道理（「要定位清楚」），没有操作；步骤超过 3 个，每个都讲不透。

## 观点（约 1 分半，350～420 字）

适合：「我认为……」「别再……」「为什么……」。

| 段落 | 占比 | 要做的事 |
|---|---|---|
| 开头 | 约 15% | 直接表态，或说一个反常的事实 |
| 大家通常怎么想 | 约 15% | 说清常见看法，以及它为什么听着有道理 |
| 证据 | 约 40% | 一件他亲历的事，讲到时间、场景、怎么做、结果 |
| 道理 | 约 20% | 常见看法漏了什么；什么情况下他的判断成立 |
| 收住 | 约 10% | 一句回扣开头的话 + 一个可做的动作 |

必备料：一个明确判断；至少一件能证明它的亲身经历。

常见问题：全是观点没有事，或事讲完没扣回观点。

## 故事（约 1 分半，350～450 字）

适合：「那次……」「我经历过……」。

| 段落 | 占比 | 要做的事 |
|---|---|---|
| 开头 | 约 12% | 从最紧张或最反常的那一刻切进去 |
| 背景 | 约 15% | 当时是什么情况，用一两句交代 |
| 经过 | 约 40% | 发生了什么、他怎么选的、哪里出了岔子 |
| 转折 | 约 15% | 结果和预想不一样的地方 |
| 提炼 | 约 18% | 他从中得出的一条判断 + 观众能用的一件事 |

必备料：时间、场景、人物、他当时的选择、结果。

常见问题：平铺直叙从头讲起，开头没有钩子；讲完没有提炼。

## 写法对照

下面用同一段意思，对比「一句一段」和「连成一段」。事实不变，只改怎么说。

差（句子孤零零，观众得自己补逻辑）：

```text
大部分人刷到这种消息，会直接做成一条资讯播报。三句话说完，划走。

我没做。

我先想一件事：这个东西，能不能放进一个场景里。
```

好（前句留下的问题，后句接住）：

```text
大部分人刷到这种消息，会直接做成一条资讯播报，三句话说完，观众也就划走了。我没急着做，先想了一件事：这个大脑模型，能不能放进一个场景里，让人一眼就看见它是什么样子。
```

再往下，要把「场景」讲出来：场景里有什么、观众看到了什么、为什么这样搭。这些细节档案里没有，就先问用户，不要自己编。
